What this is

The outline (sections §1 to §8) describes the model. This prototype shows the surfaces that ship — restructured to match what's currently live at dev.conductor.askmaestro.ai/tasks.

Two surfaces in v1:

  • Tasks page — one shared inbox with tabs: All Tasks, My Tasks, Urgent, Needs Review. AI-flagged tasks live in Needs Review tab; clicking one opens the drawer with an "ACCEPT OR DROP" block.
  • In-context create — where most tasks actually originate. Hover a client message → "Create task"; AI proactively suggests tasks inline as the conversation happens.

Patterns that overlay:

  • Task detail drawer — slides in from the right when you click a row. Shows source, tier, rationale, AI reasoning, evidence, activity log.
  • Manual create modal — press c from anywhere on the board. Title + owner only by default (preserves 2-second creation per PRD §5d); collapsible "More options" reveals priority, due, type.

What's NOT here (deliberately)

  • In-context approval surfaces (composer view, trip page, ops dashboard). The PRD's dominant approval flow lives in the real app where messages and trips already render. These mockups isolate the dedicated task surfaces only.
  • Phase 2 task types (member-context, ops-internal, agent-subtask) and Phase 3 (compliance-safety, discovery).
  • Auto-approval threshold tuning UI (v2).
  • Real data. Every task, name, rationale below is fabricated for the demo.
