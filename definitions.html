Notion outline (source of truth)

Definitions

Locked vocabulary for the alignment meeting

Task

A discrete actionable item that needs to happen for a trip to be delivered correctly. Has an owner (human or AI), a definition of done, and a closeable lifecycle.

Signal

A raw event or sensed condition that may be task-shaped — a client message, an external alert, a sensor reading, a scheduled-query hit. Not yet a task. The system evaluates whether to promote one or more signals into a Suggestion.

Suggestion

The system's proposed task, synthesized from one or more Signals and awaiting an Approval gate. May be auto-approved (above threshold) or routed to a human reviewer. Often simultaneous with the Signal for simple cases (one message → one suggestion); distinct when the system correlates multiple signals into one suggestion (3 messages + 1 vendor email about the same hotel issue → one suggestion, not four) or filters out signals that don't warrant a task.

Approval gate

The decision point between Suggestion and Canonical task. Two paths: auto-approval (system confidence above threshold for that origin / routing tier) or human approval (operator reviews, can edit, then approves or rejects). Manual task creation bypasses the gate.

Canonical task

The approved task record — same as Task, but emphasises that this is the single source of truth. Different surfaces (board, trip page, account page, agent mode) render this record differently. A Suggestion becomes a Canonical task once it passes the Approval gate. See §7.2 for the schema.

Origin

The why a task exists — the underlying reason it needs to happen. See §3 for the taxonomy. Distinct from creation surface (below).

Creation surface

The where / how a task was created or detected — message bubble action, inline suggestion, agent mode, trip view, signal monitor, scheduled query. A single origin can be reached from multiple surfaces. See §7.1 for the creation paths.

AI task

A task whose execution is performed by AI — either fully (auto tier) or with a human approval gate (assist / escalate tiers).

Human task

A task that requires a human (ops associate, TA, supplier-relationship owner) to execute. Typically relationship-critical, judgement-dependent, or phone-based.

Routing tier

How the task is handled. auto = AI handles end-to-end. assist = AI proposes, human approves. escalate = immediate human attention required.

Primary context anchor

The system object a task is bound to — typically trip, message/conversation, or account/member. Internal-ops tasks may be anchor-less in the data model, but the UI does not surface 'global' as a user-facing option (avoids becoming a catch-all). The anchor determines where the task surfaces (trip page, conversation thread, account view) and is the key handle for filtering.

Listening cadence

How often (or how reactively) an AI capability checks for triggers. Per-message, ambient, periodic poll, or daily batch — different per stream.

Event-driven stream

A continuous feed of events arriving in our system from outside that may spawn a task. See §4. (Engineering term: WRITE / push.)

Schedule-driven stream

A query we run on our own stored data on a schedule, surfacing tasks from patterns or absences. See §5. (Engineering term: READ / pull.)
